A structured, public plan to go from QA to backend engineering. Every step has a deliverable — if there's nothing to show, it isn't done.

| Block | Focus | What it proves |
|---|---|---|
| **1. API & testing foundations** | FastAPI · TDD with pytest & Docker | I can build and test an API properly |
| **2. Test automation** | Playwright · API testing · CI | I automate, and I know what *not* to automate |
| **3. Build a project** | CRUD, auth, CI/CD, OWASP API Top 10 | I ship code with a pipeline and security in mind |
| **4. Take it to production** | Terraform · AWS · OAuth2 in depth | I can run a system, not just write one |
| **5. Quality & performance** | E2E · Locust · Redis caching | I measure instead of guessing |
| **6. Architecture** | Celery · multi-tenancy · OpenTelemetry | I design distributed systems and observe them |
| **7. Data depth** | PostgreSQL internals · data-intensive design | I make things fast on purpose |

**Learning principle:** learn it when there's a real problem for it, then apply it immediately — either in a new project or by refactoring an existing one. Reading a doc is not a milestone; a working, tested, deployed thing is.
